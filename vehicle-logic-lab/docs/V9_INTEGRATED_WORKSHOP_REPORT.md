# v0.9 — 같은 차를 조립하고, 제어하고, 주행하기

2026-10-20~21. 이번 배포는 **전진 구동계 한 모듈의 완결된 제작 흐름**이다. 차량 전체/상용 게임/OEM 교육 납품이 끝났다는 의미가 아니다. 독립 폴더 `vehicle-logic-lab` 안에서 실행한다. 팀원 원본과 부모 프로젝트는 수정하지 않았다.

## 이번에 실제로 연결한 것

`부품 위치·방향 맞추기 → 볼트 고정 → 전력/요청 배선 → 같은 차의 수치 제어기 → 정상 요구사항 대조 → 실제 Rapier 주행`

- 메인 **내 EV 조립하기**가 새 통합 공방으로 진입한다. 기존 READY 모험은 별도 학습 메뉴와 저장을 유지한다. 본편 앱으로 리디렉션하지 않는다.
- 모터·감속기·구동축·바퀴 4개·배터리·인버터·페달/제어기 총 10개. 놓기와 고정이 서로 다른 상태다. 드래그/회전/스냅 판정, 위치 맞춤 도움, 꾹 누르는 볼트 고정, 부품 꺼내기를 제공한다. 단계가 맞지 않거나 다른 부품을 고정하기 전에는 조립하지 못한다.
- 배터리→인버터, 인버터→모터, 페달/제어기→인버터의 3개 경로. 3D 단자 또는 접근성 대체 단자를 클릭→클릭 연결한다. 미조립/미배선은 실제 구동 허용을 차단한다. 부품을 꺼내면 관련 케이블도 해제된다.
- 원래 흰둥 형상을 유지했다. 정비 고양이가 작업 부품 곁으로 이동하고 몸을 숙여 렌치를 돌린다. 운전 고양이는 주행 차량에 탄다. 고정 성공음, 시동음, 주행 소리가 있다. 외부 캐릭터/브랜드 자산을 복제하지 않았다.
- 조립/로직/시험 화면을 이동해도 하나의 Canvas·Physics·차량 실행기를 유지한다. 바깥 주행 시점, 방향키/WASD 가속·제동·조향, 3D START·P/D·페달, 회전/줌/분해 보기를 제공한다. START는 P+브레이크에서 READY를 허용하는 **제공된 시험 장치**다.
- 공방 UI를 차량 뷰/작업 영역/단계/대화로 다시 나눴다. 고정 높이 안의 독립 스크롤, 작은 화면의 세로 배치, 자세한 요구사항과 조작 도움의 접기/펼치기, 로직 확대/축소를 제공한다. 기존 화면의 최소 660px 높이가 공방 하단을 자르는 문제를 공방에 한해 제거했다.

## 로직은 선 연결 정답지가 아니라 실행되는 수치 제어기

`TRAINING-DRIVE-1.0`의 7개 블록을 재사용한다. %, ms, bool, Nm 포트를 구분한다. 이중 채널 차이/유효 시간, 이득, 가용 토크 상한, READY·D·제동 우선, 상승/하강 변화율, 즉시 차단을 실행한다.

처음에는 허용→변화율, 변화율→명령의 두 선이 없고 이득/상승률도 요구사항과 다르다. 단순히 연결만 끝내도 통과하지 않는다. 정상 50%→90Nm, 20ms마다 최대 +1.2Nm 등의 요구사항에 맞춰 수치를 조정해야 한다. 단위 오류/순환/구조 오류는 별도로 거부한다. 예제 적용은 보조 사용으로 기록한다.

선 복잡도를 줄이기 위해 같은 제어기를 **입력 품질 / 요청·상한 / 허용·동특성·명령**의 세 관점으로 나눈다. 전체 맥락 띠와 숨겨진 상류 블록 링크를 남긴다. 현재 포트 값, 미연결, 조건 결과, 목표/실제 토크가 카드에 표시된다. 모든 영역이 다른 문제가 아니라 같은 그래프의 관점이다. 자유 형상/노드 추가 편집기는 이번 공방의 범위가 아니다. 기존 READY 보드의 우클릭 배치 편집은 유지한다.

독립 오라클 19개 조건은 제공된 정상/경계/비정상 시나리오와 같은 설계를 대조한다. 최초 차이 시각, 기대/실제 Nm, 요구사항 ID·시험 기법을 보여 준다. 이는 TC를 직접 설계하는 교육이나 MC/DC 달성으로 포장하지 않는다.

## 동기화의 기술적 경계

새 `WorkshopController`는 `VehicleSwPort`의 `TRAINING_COMPOSED` 구현이다.

1. 기존 C/WASM은 적용 기어·인터록을 맡는다. 기존 C의 VMC/eDrive 출력을 그대로 쓴다고 주장하지 않는다.
2. 실제 DriverInputRuntime의 가속/제동, 적용 기어, 하드웨어·READY 게이트가 학습 그래프에 들어간다.
3. **기존 60Hz 물리 소유자 하나**에서 누산기로 20ms 제어를 실행하고 sample/hold한다. React 타이머가 별도로 토크를 만들어 물리 명령을 뒤에서 덮어쓰지 않는다.
4. 사용자 그래프의 최종 Nm가 기존 어댑터를 거쳐 실제 Rapier 힘·속도·위치로 전달된다. 그래프 변경 시 제어기 메모리를 리셋한다. 하드웨어/READY/입력 validity 상실은 즉시 구동을 차단한다.
5. 모터/감속기/바퀴 회전은 실제 종방향 속도와 기어비에서 계산한다. 정차 시 명령만 들어왔다고 차가 회전하는 가짜 애니메이션을 만들지 않는다. 케이블의 이동 표시는 경로 개념 표현이지 측정 전류가 아니다.

새 공방의 가정: 감속비 7:1, 효율 0.9, 바퀴 반지름 0.425m, 질량 1200kg. 힘 변환은 `Nm × 7 × 0.9 / 0.425`다. 이는 특정 EV 제원/OEM 승인값이 아니다. 기존 경량 아케이드 차량 기본값은 바꾸지 않았다. 질량만 선택적으로 지정하는 Rapier 어댑터 옵션을 추가했다. pitch/roll 고정, 감쇠, 마찰, 단순 제동 등 아케이드 가정은 남아 있다.

기존 물리 어댑터는 제동 입력이 있으면 구동력을 우선 차단한다. 학습 사양의 5% 경계 시험과 모든 아날로그 물리 경계가 동일하다고 주장하지 않는다. 기존 `SystemStudio`의 추가 상한 시연도 그대로 남아 있으며 새 공방과 구분한다. 전체 과거 실행기를 새 구조로 이식한 것은 아니다.

## 누적 성취와 근거

- 조립 10/10·배선 3/3, 독립 로직 19/19, 실제 주행 관찰을 각각 표시한다. 제작 완료는 하드웨어와 해당 그래프의 검증 식별자가 함께 일치해야 한다.
- 그래프 변경은 로직 인증과 이번 주행 관찰을 해제한다. 하드웨어/배선/그래프 구성이 달라지면 제어기의 누적 주행·제동 기록도 초기화한다. 무동력 관성 주행만으로 새 설계의 구동 관찰을 채우지 않는다. 저장을 읽을 때도 인증을 재계산한다. 조립/배선/설계는 `vehicle-logic-lab.workshop.v1`에 함께 저장한다. 기존 READY 키는 덮어쓰지 않는다.
- 우측 상단 **새 차**는 확인 후 새 프레임/설계로 시작한다. 이전 제작 기록을 먼저 `vehicle-logic-lab.workshop.v1.backup.<시각>` 키에 보관하며, 저장 실패 시 새 제작을 중단한다. 현재 게임 내 백업 목록/자동 복원 UI는 없으므로 전달할 근거는 먼저 JSON으로 내보내는 편이 좋다. DOM 테스트는 취소/새 제작/기존 기록 백업을 확인한다.
- 25m 이상 실제로 달리고 브레이크로 정차하면 현재 세션의 **주행 관찰** 표시가 남는다. 이것을 독립 물리 오라클의 PASS로 부르지 않는다. 이 관찰 표시는 재진입 시 초기화되며 영구 주행 이력 기능이 아니다.
- 설계 근거 JSON은 사양·가정·하드웨어·그래프·식별자·보조 사용·독립 시험 샘플·현재 주행 관찰을 담는다. 자동 가져오기/물리 시간축 재생 기능은 아니다.

## 다음 요청으로 나눌 완료 단위

1. **같은 차에 제동 기능 추가**: 캘리퍼/디스크/페달 조립 → 압력/마찰 제동의 정상 요구사항 → 단위 있는 제어 → 독립 정지 기준·시험 근거 → 같은 차 주행. 회생제동은 SOC/속도/모터 한계 모델 없이는 구현했다고 표시하지 않는다.
2. **같은 차에 조향 기능 추가**: 랙/스티어링 조립 → 핸들각·조향비·차속별 제한 → 바퀴각·궤적 → 요구사항 대조. 완료 영역만 차 위에서 성장시킨다.
3. **실무 검증 심화**: 제어 입력/분기/명령/힘/응답의 동기 시간축 기록, 단위/통합/물리 시험 경계, 독립 허용오차, 고장 주입→증거→수리→동일 조건 재주행. 제품 방향 Phase A→E를 지킨다. TC 저작·커버리지와 AUTOSAR SWC/RTE/BSW/ARXML은 별도 검수 범위다.
4. **상용 품질 아트/접근성/성능 패스**: 정교한 차량/부품 모델·재질·캐릭터 애니메이션, 손/렌치 접촉과 카메라 연출, 게임패드·저사양 성능, 해상도별 GPU/EXE 플레이 QA. 현재 절차적 3D 모델을 Switch 판매 수준 완성 아트라고 부르지 않는다.

포트폴리오는 ‘차량 전체를 구현한 양산급 디지털 트윈’보다 **정상 요구사항 → 실행 모델 → 조립 상태/기능 계약 → 같은 물리 실행 → 독립 검증과 한계**의 추적 가능성으로 제시한다. 지금 완료한 모듈의 잘못된 설계가 실제 명령·시험 결과를 바꾸는 시연이 핵심 증거다.
