# v0.15 — 완주 가능성과 기능별 복구 루프

## 냉정한 역평가

이전 버전은 기능을 추가한 양에 비해 플레이 흐름의 완성도가 부족했다. 한 사이클을 끝내지 못한 것은 자동차 공부가 어려워서만이 아니다. 모든 부품 조립 뒤에야 로직을 배우는 긴 간격, 분산된 다음 버튼, 실행과 판정의 분리, 경계가 안 보이는 퍼즐이 주요 원인이었다. 지도와 정보 패널을 더 붙이는 것으로 해결했다고 볼 수 없다.

| 관점 | 현재 판정 | 근거와 공백 |
|---|---|---|
| 기초 구동 | 일부 구현 | 구동·감속 전달·바퀴·제동·조향·제공 현가. 실제 차량의 모든 부품/하위 구조를 다룬 것은 아님 |
| EV 전체 아키텍처 | 부족 | BMS, 프리차지/접촉기/HV 인터록, 저전압/DC-DC, 충전/OBC, 열관리, 네트워크·진단·고장 협조는 독립 콘텐츠 미구현 |
| SW 기술 학습 | 구동 입문 한정 | 직접 만드는 것은 VCU 요청 계산·허용 조건·명령 동특성. 제동 ECU/EPS/현가 제어 SW를 만든 것으로 세지 않음 |
| 초심자 완주·정보량 | 흐름 개선, 교육 효과 미검증 | 짧은 기능 루프·고정 다음 행동·선택적 도움 구현. 신규 사용자 3~5명의 완주/이탈 관찰은 아직 없음 |
| 재미 | 보장할 수 없음 | 복구 누적/차량 변화/선택/주행 보상은 있으나 반복 연결의 재미와 연출은 여전히 평가·개선 필요 |
| Switch 판매 품질 | 미달 | 절차적 모델/제한적 리그와 코스, 장면 간 아트 격차, 컨트롤러 중심 전체 UX와 타깃 기기 성능 QA 부재. Switch 패키지도 아님 |
| 검증 기업 신입 독립 교육 | 미달 | 진행자 동반 구동 로직 입문 데모 가능성은 있으나 전체 도메인·시험 설계/커버리지·검증 수준별 커리큘럼과 교육 담당자 검수가 부족 |
| 포트폴리오 | 의미 있는 프로토타입 | 실행 모델·독립 기대값·실패 후 수정·회귀·물리 명령 연결이 강점. 양산 ECU/HIL/인증/AUTOSAR 전체 구현으로 포장하면 안 됨 |

잠깐 움직이는 단순 모형과 지속 운용 가능한 EV 전체는 다르다. 충전·열관리 등을 모두 단기 출발의 필수 조건으로 묶지는 않는다. [DOE EV 구성요소](https://afdc.energy.gov/vehicles/how-do-all-electric-cars-work)와 구현을 대조했다. 설계 알고리즘과 독립된 요구 기준으로 시험한다는 [MathWorks 모델 기반 시험 설명](https://www.mathworks.com/discovery/model-based-testing.html)의 취지는 유지한다. 출처가 게임의 정확성이나 교육 효과를 인증하는 것은 아니다.

## 검수 중 추가로 잡은 진행 오류

- 실행 탭에서 도움 화면의 아래쪽 스크롤이 남아 블록 대신 빈 격자가 보이던 문제: 단계/기능/탭 전환 시 작업대 스크롤을 0으로 복원하고 블록 높이를 실제 포트 수에 맞췄다.
- 레이스 표시용 React 상태가 아직 표시하지 않은 누적 시간을 덮어쓰던 문제: 누적 상태 소유자를 분리했다. 60Hz 입력/10Hz 화면 갱신 회귀가 수정 전에는 결말 도달에 실패했고 수정 후 통과한다.
- 앞 기능을 다시 수정할 때 현재 조립 묶음과 뒤 모듈의 빈 연결 때문에 재진행이 막히던 문제: 해당 기능 묶음으로 돌아가며 이후 부분은 제공 구현으로 두고 완료 기록은 취소한다. 현재 퍼즐 정답을 자동 완성하지 않는다.
- 제공된 원시 센서 배선을 삭제해 초급 도움으로도 복구할 수 없던 경로: 제공 배선은 읽기 전용, 현재 제작 입력의 배선만 수정 가능하게 했다.
- 차고 설계도 버튼이 공통 주 버튼 숨김 규칙에 같이 숨던 문제와 차고 재제작의 시작 묶음을 수정했다.
- 새 탭은 시작하기 하나, 같은 탭의 진행 중 새로고침은 현재 모험 복원. 직접 타이틀로 나갔을 때에는 다시 새 모험을 시작한다. 기존 저장은 삭제하지 않는다.

## 기본 흐름

구매 → 시운전/자동 사건 → 복구 지도 한 번 →
회전 전달 장착/관찰/복구 → 바퀴 장착/관찰/복구 → 전력 장착/관찰/복구 →
페달·VCU 장착/관찰/요청 SW/실행/복구 → 제동 장착/관찰/구동 허용 SW/실행/복구 →
조향 장착/관찰/구동 명령 SW/실행/복구 → 통합 시험 → 대회(완주 도우미 선택) → 시상식 → 차고.

마지막 SW는 조향 제어가 아니라 VCU 구동 명령 통합이다. 기본 제동·조향은 제공 모델. 회전 애니메이션을 실제 부하·전압·발열 해석으로 설명하지 않는다. 하드웨어 고정, 원리 관찰, SW 검증을 각각 기록한다.

## 변경과 재사용

유지: 15장치/6하네스, TorqueModel, 독립 19시나리오, C/WASM/Rapier, 기존 흰둥·밝은 UI, 원본 프로젝트와 기존 release. 검수되지 않은 과거 데이터를 정답으로 새로 사용하지 않았다.

신규: `restoreLoop.ts`, `PartExhibit.tsx`, `JourneyRail.tsx`, `restoration.css`, `tests/restoration.test.mjs`.

주요 수정: 캠페인/저장 복원/메뉴, 조립, 퍼즐·설명·실행 피드백, 이동 경로, 차량/도로/파손, 부품 움직임. Sites 로컬 절차에 따라 배포와 개발 화면을 분리하고 재배치를 실제 화면에서 확인했다.

## 다음 완결 단위

1. 제동 독립 에피소드: 페달 센싱→요청/회생·마찰 협조의 검수된 교육 사양, 별도 요구/판정, 부품·시뮬레이션·신호 추적. 제공 제동 모델을 대체한 범위만 표시하고 구동 회귀 보존.
2. 아트 정식 제작: 원본 차량 모델/캐릭터 리그·접촉, 일관된 트랙/정비소, 실제 기기 성능. 도형 추가만으로 상용 품질이라고 주장하지 않기.
3. 신규 사용자 3~5명 완주·도움 사용·이탈 기록, 기능 후 입력→연산→장치 설명 및 새 조건 예측 평가. 기업 교육 활용 전 교육 담당자의 요구/시험/커버리지 검수.

실행/검사 범위는 `qa-v15/RESULTS.md`를 따른다. 기존 저장은 삭제하지 않는다. 새 복구 순서는 타이틀의 시작하기로 시작하며 이전 진행은 내부 백업된다.
