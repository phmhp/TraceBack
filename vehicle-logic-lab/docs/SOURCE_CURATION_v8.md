# 기존 정보 선별 — v0.8

목표는 EV의 운전자 요청 → 조건/상태 → 명령 → 차량 반응을 이해하는 것이다. 원본 자료가 많다는 이유로 전부 학습 화면에 나열하지 않는다. 분류의 근거는 이 프로젝트에 복사된 실행 소스와 `simulation/src/referenceVehicle/generated/reference-vehicle-registry.json`이다. 프로젝트 내부 APPROVED가 OEM 승인이나 양산 적용 근거는 아니다.

## 지금 쓰는 자료

| 출처/경계 | 학습에 쓰는 방법 | 범위 구분 |
|---|---|---|
| DriverInputRuntime.accelerator | 페달 0~1 → C 입력 → 정규화 구동 요구 | canonical 센서 %와 별칭으로 묶지 않음 |
| LF-GEAR-INTERLOCK | D/R 요청과 적용 기어·수락 여부를 같은 실행에서 비교 | 게임용 속도 조건, 양산 사양 아님 |
| LF-PROP-INTERP | 입력 유효성·방향·크기 해석 | 실제 C 스냅샷 |
| LF-PROP-GEN | 정규화 요구와 속도 → Nm 변환 | 기존 VMC 보정 맵 |
| LF-PROP-EDRV | 토크 요구 → 제한 후 명령 | 실제 모터 토크 측정이 아님 |
| DriveTorqueRequest | VMC/eDrive 경계의 크기·방향·유효성 | 인터페이스 책임과 단위 학습 |
| EDriveCommand | SW 명령 → 힘 변환 → 물리 속도 | 명령과 물리 응답 분리 |
| DriverInputRuntime.brake | 입력 → 마찰 제동력 명령 → 가속도/속도 변화 | 기존 TS·Rapier, ABS/회생 배분 아님 |
| DriverInputRuntime.steering | 정규화 조향 → 속도 기반 앞바퀴 각도 → 주행 | -1~1, rad, ° 구분 |

READY 정상 요구사항은 `src/content/ready.ts`의 명시적인 교육용 사양을 쓴다. 입력 조합, 새 버튼 이벤트, 상태 유지와 전이, 출력 허용을 같은 기능의 하위 단계로 학습한다. 구동 제작은 `TRAINING-DRIVE-1.0`의 유효성·이득·상한·제동 우선·변화율 제한을 사용한다. 기존 OEM 요구사항인 것처럼 이름을 바꾸지 않는다.

## 참고 또는 보류

| 자료 | 결정 | 이유 |
|---|---|---|
| IFC-DESIGN-003 | 참고만 | PropulsionRequest 별칭 미승인, 실행 계약으로 승격하지 않음 |
| ActualDriveTorque | 보류 | 독립 측정/추정 생산자 없음. 명령을 복제해 actual로 표시하면 검증을 속이게 됨 |
| LF-BRK-BLEND | 보류 | 회생/마찰 배분과 에너지 제약 모델 부재 |
| EnergyDriveTorqueLimit | 보류 | 실제 생산자 없음. 학습용 수동 토크 cap을 배터리 계산 결과로 부르지 않음 |
| 기존 고장 사례·TC | 원본 보존, 신규 미션 채점에 일괄 적용하지 않음 | 초기조건·자극·독립 기대값·복구 조건을 학습 모델에 맞춰 검수해야 함 |
| AUTOSAR/SWC/RTE/BSW 자료 | 선택 설명 | 기능을 이해한 뒤 배치 관점으로 연결. 실제 RTE/BSW/OS 실행·ARXML 생성 아님 |

539개 참고 항목은 보존하되 기본 진입점에서 제거했다. 선별한 실행 자료 9개만 지도에서 선택적으로 펼친다. 데이터 ID 존재 여부와 보류 항목 분류는 자동 테스트한다. ID가 존재한다는 사실만으로 기술 내용 전체가 검증되는 것은 아니다.

## 다음 누적 단위

READY → 기어 인터록 → 구동 → 제동 우선 → 에너지 제약 순으로 같은 차량에 누적한다. 각 단위는 정상 요구사항, 입력/출력과 단위, 상태/시간, 실제 실행 관찰, 독립 기대값이 먼저 있어야 한다. 사건·단서·수리·재주행은 제품 방향 문서 Phase A→E 순서로 편입한다. TC 설계/단위·통합·임베디드 시험 레이어는 이를 명시적으로 가르칠 콘텐츠와 채점 근거가 준비된 뒤 별도 학습 목표로 도입한다.
