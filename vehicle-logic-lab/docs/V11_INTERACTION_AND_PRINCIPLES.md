# v0.11 — 한 커서로 조작하고, 움직임을 보고, ECU 로직을 만들기

2026-10-21. 기존 EP.01을 개선하는 변경이며 다른 본편 앱/정보 포털로 전환하지 않는다. 부모 및 팀원 원본은 그대로 두고 독립 폴더 내부에서만 구현했다. Sites의 로컬 구현·미리보기 검수 흐름을 사용했으며 외부 서비스로 게시하지 않았다.

## 원인과 조작 수정

v0.10의 화면 브레이크는 pointer-up에서 즉시 풀렸다. 따라서 마우스로 페달을 누른 뒤 START로 이동할 수 없었고, P/OFF/브레이크 유지/미완성 설계 등 여러 정차 원인을 구분하는 안내도 부족했다. 실제 물리 실행기는 정상 설계로 움직였지만 조작 UX가 그 진입을 막았다.

지금은 화면과 3D 브레이크를 클릭하여 **밟기 유지/해제**할 수 있다. 이것은 가상 운전자의 발을 유지하는 접근성 보조이며 START 조건을 삭제한 것이 아니다. 브레이크 유지 → START → D → 브레이크 해제를 각각 클릭한 뒤 ↑ 또는 가속을 누른다. 화면은 READY·요청 기어/실제 기어·제동·속도와 정차 원인을 보여 준다. 브레이크가 남아 있으면 대회 카운트다운을 시작하지 못한다. 움직이는 중 START로 시동을 끄지 않는다. 일시정지·포커스 상실은 운전 입력을 해제한다.

## 그래픽과 모모의 행동

- TV 화면은 실제 별도 Three.js 장면을 render target으로 그리는 **자체 제작 레이싱 단편**이다. 단순 정지 사진이 아니다. 화면 반사광, 영화관 와이드→얼굴 클로즈업, 팝콘 컵, 먹는 팔 동작, 놀라는 눈 크기 변화가 있다. 어두운 배경은 영화관 장면 안에만 한정하고 나머지 게임은 밝게 유지한다. 일시정지/움직임 줄이기를 지원한다.
- 영화 제목은 모모의 동기로 언급하지만 원본 영화 영상/스틸/음악/대사/로고를 포함하지 않았다. 실제 영화 영상으로 오해하지 않도록 화면에 자체 제작 단편임을 표시한다. 기존 진행의 모험 메뉴에서 인트로를 다시 볼 수 있다.
- 원래 모모의 얼굴·몸체를 유지하고 다리/발을 추가했다. 작업 위치의 부품 높이에 캐릭터를 띄우던 방식 대신 바닥 y=0을 유지하며 차 끝을 돌아 걸어간다. 보행 다리/팔, 부품 운반, 몸 숙이기·렌치·땀과 노력 표정을 추가했다. 부품 놓기/배선 완료는 도착 및 작업 애니메이션 뒤 실제 상태에 반영한다. 작업 중 중복 입력을 막고 중단/재접속하면 마지막 확정된 조립 상태에서 다시 시작한다.
- procedural 모션이다. 손-공구-볼트 접촉 IK, 세밀한 표정 리깅, 상용 컷신 아트·사운드 파이프라인을 완성했다고 주장하지 않는다.

## EV 구성과 소프트웨어 학습

이번 캠페인은 가속페달 **센서**와 별도 **VCU(차량 제어 ECU)**를 구분한다. 센서 값 → VCU 입력, VCU 명령 → 인버터 입력의 연결을 각각 만들고, 배터리 전력선과 구분한다. ECU 미장착이나 센서선 누락은 실제 구동력을 차단한다. 기존 자유 제작실의 통합 페달/제어기 모듈은 보존했다. v0.10 저장은 진행을 지우지 않고 ECU/센서 경로를 제공된 기존 부품으로 보완한다.

HPC를 모든 EV에 별도 필수 박스처럼 추가하지 않는다. 이 차량은 별도 VCU가 있는 가상 교육 구성이다. HPC/중앙 컴퓨터는 여러 제어 기능을 통합하는 다른 E/E 구성이라는 차이를 지도에서 설명한다. 실제 ECU 부팅·BSW·CAN 프레임·통신 지연·저전압 전원망을 모델링한 것은 아니다.

하드웨어 복구 다음에 **03 · 부품에서 소프트웨어로** 단계를 추가했다. 전력, 구동, 제동의 정상 동작을 먼저 시연하고 다음 퍼즐이 ECU 안의 소프트웨어 제작이라는 소제목을 유지한다.

1. 에너지: 배터리 DC → 인버터 AC → 모터의 기계 출력.
2. 제어: 페달 센서 → VCU의 목표·허용·변화율 계산 → 인버터의 토크 명령.
3. 기계: 모터 → 감속·차동기어 → 축 → 바퀴.
4. 제동: 구동 명령 0과 실제 정지는 다르다. 별도 제공된 마찰제동이 감속을 담당한다. 회생제동은 아직 없다.

Nm를 전류나 전력으로 표현하지 않는다. 정상 원리 후 %, Nm, Nm/s, 20ms의 의미를 설명한다. 제동 차단 경계도 이제 0/5/10% 중 선택하여 정상 요구사항에 맞추므로 선 연결만으로 완료할 수 없다. 수치·단위·역할은 교육 사양이며 JKEV/OEM 양산값으로 표현하지 않는다.

참고한 공개 1차 자료: [Bosch 전기 구동 모듈](https://www.bosch-mobility.com/en/solutions/electric-motors/electric-drive-module/)의 DC/AC·전력/기계 에너지 구분, [Bosch 전기 모터](https://www.bosch-mobility.com/en/solutions/powertrain/battery-electric/electric-motors-and-active-parts/)의 기계 출력 역할, [NXP 중앙 제어 구성 설명](https://community.nxp.com/t5/NXP-Tech-Blog/S32N-Family-of-Processors-Super-Integrates-Vehicle-Functions-for/ba-p/1842659)의 개별 ECU 기능 통합 개념을 참고했다. 자료의 제품 파라미터나 인증을 이 게임의 성능으로 가져오지 않았다.

## 퍼즐과 누적 지도

연결 전 입력 슬롯에는 정답 포트 이름 대신 빈 입력/조건을 표시한다. 출처와 역할은 플레이어가 연결한 뒤 드러난다. 인터페이스 이름이 필요한 사용자를 위한 포트 도움은 선택 사항이다. AND 카드가 미리 READY·D·브레이크 5% 정답식을 보여 주던 것도 제거했다. 실제 설정 값과 연결 상태를 표시하고, 정상 시나리오의 동작 판정으로 통과를 결정한다.

각 퍼즐을 통과하면 같은 차량의 지도에서 누적된 경로를 확인한다. 지도는 실제 EGraph의 연결만 그리며, 빈 소프트웨어 선을 정답 그림으로 미리 그리지 않는다. 제공 모듈과 직접 잇는 연결, ECU 안의 기능과 아래의 전력·기계 경로를 구분한다. 노드를 누르면 차량의 관련 부품에 초점을 돌린다. 전체 지도는 선택 오버레이이며 기본 왼쪽 퍼즐/오른쪽 차량 배치를 유지한다.

## 호스 효과와 실제 시뮬레이션의 차이

v0.10 벤치는 TorqueModel만 별도로 실행하고 실제 차량 물리는 suspended였다. 따라서 선 위의 이동 효과만 보였다는 피드백이 맞다.

v0.11의 원리 관찰/퍼즐/시험 화면은 같은 C/WASM+WorkshopController+Rapier 실행기를 사용한다. READY·기어·페달·제동·이중 채널·신호 나이·상한이 같은 경로로 들어가고 사용자 그래프의 Nm가 실제 힘으로 전달된다. 차체 위치는 관찰을 위해 고정해 그리지만, 가상 차량의 속도와 실제 종방향 상태에 따라 모터 축·기어·바퀴를 움직인다. 모터 단면에는 고정자/회전자, 브레이크에는 디스크 회전과 패드 압착을 표현했다. 주행 화면에서도 XRAY를 켤 수 있다.

정상 원리 관찰은 명확히 **제공 정상 모델**로 표시하고, 퍼즐/시험은 **내 VCU 로직**으로 표시한다. 시연을 봤다고 사용자 그래프가 자동으로 완성되지는 않는다. 케이블 효과는 개념 경로일 뿐 전류 측정값이 아니다. 모터 전자기 FEA, 인버터 PWM·상전류, 유압 회로, ABS, BMS/SOC, 회생제동, 양산 차체/타이어 동역학은 구현 범위가 아니다. 회전 비율은 속도·반지름·감속비에 따른 운동학적 표현이다.

제공된 벤치 시험의 PASS는 **독립 논리 기대값과 20ms 모델 샘플**의 대조다. 옆의 물리 동작은 관찰이며 물리 오라클 인증이나 MIL/SIL/HIL 적합성 판정을 추가한 것이 아니다. 제동 입력이 조금이라도 있으면 구동력을 차단하는 기존 물리 어댑터 가정과 논리 요구사항의 5% 경계는 구분한다.
