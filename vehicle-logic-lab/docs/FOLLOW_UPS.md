## v0.7.1 — 클릭·드래그 빈 화면 수정

운전자 화면의 `setLook` 지연 updater가 pointer-up 후 지워진 `drag.current.x/y`를 읽는 오류를 StrictMode/실제 DOM 이벤트로 재현하고 수정했다. 좌표 차이를 동기적으로 복사하고 pointer-up/cancel/lost-capture에서 정리한다. `GameRecovery`는 다른 렌더링 예외에도 공백 대신 재진입 UI를 표시하고 진행/설계 키를 삭제하지 않는다. `npm run test:click-safety`에 회귀가 있다. 추후 UI 수정 시 반드시 실행하고, 실제 GPU QA는 별도로 수행한다. 전달 범위는 루트 `HANDOFF.md`를 따른다.

목적: 실제 로직 결과가 기존 차량 동작에 반영되는 체험.

> 원본 `trackback-v2/src/app/GameApplication.tsx`, `runtime/SimulationRuntime.ts`, `physics/rapier/RapierVehiclePhysics.ts`, `runtime/c/`와 필요한 map·asset 의존성을 먼저 분석하라. READY 로직의 `Snapshot.outputs.drive`를 명시적 포트 계약으로 받아 실제 추진 허용에 반영하는 어댑터를 구현하라. 필요 소스·WASM·데이터는 검토 후 이 프로젝트 내부로 복사하여 독립성을 유지하라. 기존 C/Rapier 제어·물리를 단순 애니메이션으로 대체하지 말라. `ui/VehicleView.tsx`는 현재 정적 모델임을 고려하라. 완료 기준: 구동 차단 시 추진 불가, 허용 시 실제 물리 동작, 입력 시퀀스 회귀 시험, 원본 경로 의존 없음, 연동 성공 후에만 테스트 트랙 메뉴 활성화. 해당 작업이 없으면 메뉴는 추가 예정 유지.

## P3 — 문제 해결 챌린지 (P1 검수 및 READY 학습 이후)

목적: 배운 기능에 잘못된 연결을 넣고 진단·수정·재검증.

> `engine/graph.ts`, `engine/verification.ts`, `ui/App.tsx`의 실제 실행·시험 결과를 재사용하여 READY 오류 챌린지를 추가하라. 원본 `runtime/investigation/InvestigationSession.ts`, `Evidence.ts`, `ui/investigation/`의 단서·비교 패턴을 분석해 필요한 작은 단위만 포팅하라. 실패 시험은 원인 정답이 아닌 현상 증거로 취급한다. 플레이어가 조건 누락을 관찰하고 연결을 고친 다음 동일 시험으로 통과해야 완료된다. 완료 기준: 실제 결함 주입→증거 비교→수정→재검증, 원본 보존, 검수되지 않은 ECU 정보 비노출, 신규 메뉴 실제 기능 확인 후 활성화.

## P4 — 편집·시각화 고도화 (MVP 이후 독립 실행 가능)

목적: 큰 그래프와 다양한 화면에서 조작성을 개선.

> `ui/LogicEditor.tsx`, `ui/styles.css`, `ui/VehicleView.tsx`, `ui/Dashboard.tsx`를 개선하라. 복사된 차량 모델과 현재 SVG 노드 좌표 구조를 우선 재사용한다. 휠 포인터 중심 확대, 미니맵, 키보드 블록 이동, 연결 드래그 프리뷰, 상태 변화와 차량 조명 동기화를 추가하라. 계기판은 실제 `Snapshot`만 소비하고 가짜 이동·배터리 수치를 추가하지 않는다. 완료 기준: 연결·삭제·undo/redo 회귀 없음, 큰 그래프 탐색, 작은 화면 조작성, WebGL 실패 시 계기판 유지, reduced-motion 지원, 화면 QA와 결과 기록.
