# 다음 개발을 위한 독립 작업 프롬프트

## 최신 현황 — v0.6

새 게임 안에 C/WASM·Rapier 주행, 시야 조작과 페달/기어, 75m 주행 후 코믹 분해 연출, 요구사항 카드, 큰 클릭/드래그 포트, 구조/자료 탐색과 테스트 리플레이가 구현됐다. v0.5 본편 전환을 되살리지 않는다. 자세한 범위·한계와 다음 작업은 [V6 보고서](V6_EXPERIENCE_REPORT.md)를 기준으로 한다. 다음 순서: 실제 브라우저/실행파일 조작·배치 QA → 전체 시나리오의 물리 초기조건과 입력 스케줄 동기화 → 가속·제동 콘텐츠 검수·제작. 기존 READY 기대값/저장/원래 캐릭터를 보존한다.

## 최신 방향 정정 — v0.5.1

새 게임의 진행을 유지하고 원래 고양이만 적용한다. 기존 TRACKBACK 본편으로 넘기는 v0.5의 시작 연결은 사용자 의도와 달라 제거했다. 아래 v0.5 현황과 V5 보고서는 철회된 통합 시도의 기록이며 최신 UX 지시로 사용하지 않는다. `simulation/` 자산은 보존하되, 향후 필요 기능은 새 게임의 스텝바이스텝 흐름 안에서 재사용해야 한다. 외부/별도 본편 화면으로 전환하여 대신하지 않는다. 기존 저장·신호 연동·입체 부품·원화 품질을 유지한다.

## v0.5 현황

아래 P2/P3의 초기 미연동 전제는 v0.5에서 변경됐다. `simulation/`에 C/WASM·Rapier·주행·기존 추리·차량 시나리오·회귀/재주행을 로컬 복사하여 본편으로 연결했다. 자료 탐색도 539개 엔티티/2,195개 관계를 제공한다. 246개 자동 회귀 및 정적 UI 계약은 통과했지만 새 화면 실플레이 QA는 도구 차단으로 미완료다. 다음 작업은 이미 연결된 런타임을 다시 만드는 것이 아니라 실제 입력/레이아웃 QA, 사건 중간 저장, 원화와 일치하는 정식 3D 자산, 차기 case의 검수·저작이다. canonical의 DRAFT/DESIGN_ONLY/AI_DRAFT 상태는 유지한다. 최신 구체 지시문은 [V5 보고서](V5_CAMPAIGN_REPORT.md) 8절을 사용한다.

공통 조건: 이 폴더의 독립성을 유지한다. 기존 기능을 가짜 성공으로 대체하지 않는다. 기술 미검수 자료는 채점에 쓰지 않는다. 각 작업 후 실제 구현과 추가 예정을 구분한다.

## P1 — 데이터 검수 (새 도메인 콘텐츠의 선행 조건)

목적: 신규 도메인 학습에 사용할 근거 확보.

> `docs/REUSE_AUDIT.md`의 검수 대기 목록을 기준으로 원본 TRACKBACK의 요구사항·신호·인터페이스·아키텍처 자료를 읽고 검수하라. 원본은 보존하고 검토할 최소 자료를 이 프로젝트의 `docs/review/`로 복사하라. 자료별 출처·차종/제조사 적용 범위·단위·방향·검증 가능성·모순·가상 사양 구분을 기록하라. `content/ready.ts`의 명시적 가상 사양 패턴을 참고하되 실제 자동차 일반 사실로 확대하지 말라. 기존 registry drift 실패도 원인을 조사하라. 완료 기준: 검수 완료/검수 대기/사용 부적합 분류, 근거와 보류 사유, 원본 보존, 검수 완료 자료만 향후 콘텐츠 후보로 등록.

## P2 — 테스트 트랙 통합 (READY MVP 이후, 가속 콘텐츠에는 검수 필요)

목적: 실제 로직 결과가 기존 차량 동작에 반영되는 체험.

> 원본 `trackback-v2/src/app/GameApplication.tsx`, `runtime/SimulationRuntime.ts`, `physics/rapier/RapierVehiclePhysics.ts`, `runtime/c/`와 필요한 map·asset 의존성을 먼저 분석하라. READY 로직의 `Snapshot.outputs.drive`를 명시적 포트 계약으로 받아 실제 추진 허용에 반영하는 어댑터를 구현하라. 필요 소스·WASM·데이터는 검토 후 이 프로젝트 내부로 복사하여 독립성을 유지하라. 기존 C/Rapier 제어·물리를 단순 애니메이션으로 대체하지 말라. `ui/VehicleView.tsx`는 현재 정적 모델임을 고려하라. 완료 기준: 구동 차단 시 추진 불가, 허용 시 실제 물리 동작, 입력 시퀀스 회귀 시험, 원본 경로 의존 없음, 연동 성공 후에만 테스트 트랙 메뉴 활성화. 해당 작업이 없으면 메뉴는 추가 예정 유지.

## P3 — 문제 해결 챌린지 (P1 검수 및 READY 학습 이후)

목적: 배운 기능에 잘못된 연결을 넣고 진단·수정·재검증.

> `engine/graph.ts`, `engine/verification.ts`, `ui/App.tsx`의 실제 실행·시험 결과를 재사용하여 READY 오류 챌린지를 추가하라. 원본 `runtime/investigation/InvestigationSession.ts`, `Evidence.ts`, `ui/investigation/`의 단서·비교 패턴을 분석해 필요한 작은 단위만 포팅하라. 실패 시험은 원인 정답이 아닌 현상 증거로 취급한다. 플레이어가 조건 누락을 관찰하고 연결을 고친 다음 동일 시험으로 통과해야 완료된다. 완료 기준: 실제 결함 주입→증거 비교→수정→재검증, 원본 보존, 검수되지 않은 ECU 정보 비노출, 신규 메뉴 실제 기능 확인 후 활성화.

## P4 — 편집·시각화 고도화 (MVP 이후 독립 실행 가능)

목적: 큰 그래프와 다양한 화면에서 조작성을 개선.

> `ui/LogicEditor.tsx`, `ui/styles.css`, `ui/VehicleView.tsx`, `ui/Dashboard.tsx`를 개선하라. 복사된 차량 모델과 현재 SVG 노드 좌표 구조를 우선 재사용한다. 휠 포인터 중심 확대, 미니맵, 키보드 블록 이동, 연결 드래그 프리뷰, 상태 변화와 차량 조명 동기화를 추가하라. 계기판은 실제 `Snapshot`만 소비하고 가짜 이동·배터리 수치를 추가하지 않는다. 완료 기준: 연결·삭제·undo/redo 회귀 없음, 큰 그래프 탐색, 작은 화면 조작성, WebGL 실패 시 계기판 유지, reduced-motion 지원, 화면 QA와 결과 기록.
