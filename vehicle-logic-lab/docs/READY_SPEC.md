# READY 가상 차량 사양

본 문서는 사용자 개발지시서 v2.0을 실행 가능한 교육용 요구사항으로 구체화한 것입니다. 제조사·차종·표준의 사실로 사용하지 않습니다. 고전압 접촉기, 절연 감시, 인증, 실제 BMS/VCU 제어 및 안전 설계를 재현하지 않습니다.

## 요구사항

| 현재 상태 | 새로운 버튼 누름 | 추가 조건 | 다음 상태 |
|---|---|---|---|
| OFF | 있음 | 없음 | STANDBY |
| STANDBY | 있음 | 브레이크 AND 시스템 준비 | READY |
| READY | 있음 | 차량 정지 | OFF |
| 그 외 | 없음 또는 조건 불충족 | — | 현재 상태 유지 |

버튼은 false → true의 상승 에지입니다. true 유지 중에는 새 이벤트가 발생하지 않습니다. 한 실행 틱에서는 변경 전 상태를 기준으로 전이를 최대 하나만 적용합니다. 중복 전이는 명시적 오류이고 순서에 따라 선택하지 않습니다. 변경된 상태를 기준으로 출력 계기판을 갱신합니다.

- 미션 1: 초기 STANDBY. 진입 요청 = 버튼 이벤트 AND 브레이크 AND 시스템 준비. 차량 상태는 변경하지 않습니다.
- 미션 2·3: 초기 OFF(시험 시나리오는 다른 초기 상태를 지정할 수 있음). READY 상태의 활성 신호가 READY 표시와 구동 허용을 구동하도록 플레이어가 연결해야 합니다.
- 요구하지 않은 STANDBY → OFF, 시스템 준비 해제 시 READY 종료, 주행 중 고장 대응은 구현하지 않았습니다. 현재 가상 사양에서는 조건 없는 상태 유지를 적용합니다.
- READY는 움직임이나 토크의 증거가 아닙니다. 모델은 정적이고 실제 이동·물리 계산은 수행하지 않습니다.
- 실행은 입력 조작 또는 명시적 한 틱 진행으로 발생합니다. 시간 단위는 재사용한 고정 시계의 1/60초이며 ECU 실행 주기라는 의미가 아닙니다.

## 검증

- 미션 1: 진리표 8조합(필수 7, 도전 1). 정상 시동을 필수로 포함하여 항상 거짓인 설계가 통과하지 못하게 합니다.
- 미션 2: 정상 부팅, 브레이크 없음, 시스템 준비 없음, 정차 종료, 정지 없는 종료, 각 상태 유지(필수 8), 버튼 유지(도전 1).
- 미션 3: 위 9개 + 3개 초기 상태 × 16개 입력 조합 = 57개. 경계 조합마다 같은 버튼 값을 두 번 실행해 중복 이벤트도 검사합니다.
- 기대 상태·출력은 콘텐츠 요구사항에서 별도로 작성합니다. 플레이어 그래프를 기대값 계산에 재사용하지 않습니다. 여러 동등한 그래프를 허용합니다.
- 1단계: 일부 필수 시나리오 동작, 2단계: 모든 필수 통과, 3단계: 필수+도전 전체 통과. 2단계부터 다음 미션을 해금합니다.
- 출력 누락은 false와 다릅니다. 필수 출력이 없어도 false 기대값과 같다고 판정하지 않습니다.
- 내부 도어 샘플은 입력·출력·시나리오를 데이터로 등록하여 공통 엔진을 그대로 사용하는지 확인합니다. 정식 교육 콘텐츠로 공개하지 않습니다.

검증 범위는 조건 로직과 상태 제어 컴포넌트이고 환경은 브라우저 소프트웨어 시뮬레이션입니다. HIL·실차 검증으로 표시하지 않습니다.
