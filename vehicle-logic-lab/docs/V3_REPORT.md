# v3 개발 결과 — 흰둥의 꼬마차 정비소

## 1. 구현 완료

- 기존 도구형 대시보드를 기본 화면에서 분리하고, 메인 → 운전자 시점 인트로 → 정비소 → 정상 동작 체험 → 차 안쪽 → 단계별 연결 → 예측·시험 → 회귀 검증 → 복구·보상으로 재구성했습니다.
- 밝은 크림·민트·살구·라벤더, 전체 창 게임 화면, 정비 고양이 대사, 부드러운 장면 등장, 입력·연결·성공 효과음, 모험 수첩과 스티커를 구현했습니다.
- 첫 미션은 3단계, 상태 미션은 4단계로 필요한 블록만 공개합니다. 입력·AND·OR·NOT·상태·전이·출력에 서로 다른 기호·모양을 적용했습니다. 전체 그래프와 기존 자유 편집은 별도 보기로 남겼습니다.
- 운전석의 브레이크·준비·버튼은 실제 정상 기준 로직으로 계산합니다. 차량 내부는 페달 조작 → 입력 → 제어 프로그램 → 계기판 출력의 단순화된 관계를 보여줍니다. 학습 시범과 플레이어 설계는 구분했습니다.
- 검증자가 시험 상황과 예상 결과를 선택합니다. 예상 답변은 공식 기대값과 별도로 비교합니다. 요구사항 기반 전체 회귀 시험을 재실행한 후에만 기능과 스티커를 승인합니다.
- 3개 챕터의 그래프·완료·스티커·회귀 시험 증거·진행 장면을 저장합니다. 다시 실행하면 메인 화면에서 이어하기로 돌아갑니다. 이전 v2 저장은 유지하며 v3는 별도 키입니다.
- Windows용 단일 portable 실행파일, 자체 아이콘, F11 전체 화면, Esc 메뉴, 소리 크기·움직임 감소·진행 파일 이전을 제공합니다.

## 2. 기존 자산 재사용

원래 차량 모델, CatDriver, SoftShapes, 기존 그래프·연결 검사·Boolean·상태 실행·시험 엔진·미션 사양을 재사용했습니다. 기존 LogicEditor는 전체 흐름·자유 편집에서 계속 실행합니다. GuidedBoard는 같은 Graph/Wire/블록 레지스트리와 connect 함수를 사용하며 별도 가짜 퍼즐 엔진을 만들지 않았습니다.

기존 C/WASM·Rapier·레이싱·추리·기술 데이터를 삭제하거나 단순 모형으로 덮어쓰지 않았습니다. 기존 레이싱은 자체 세션·미션·C/WASM·map 의존성을 가진 독립 앱입니다. 이번 밝은 정비소의 짧은 도입에 전체 런타임을 억지로 이식하면 배포 독립성과 작업 범위가 크게 확장되므로, v3 지시서 P0의 허용 대안인 **스크립트 사고 연출**을 적용했습니다. 바깥 풍경 움직임은 이야기 연출이며 조작 가능한 레이싱이나 차량 물리 계산으로 표시하지 않습니다.

## 4. 검증 결과

- 자동 시험: 엔진·연결·상태·저장 20개 + v3 가이드·진행·보상 검증 5개 = **25/25 통과**.
- 잘못된 로직/연결/항상 거짓인 출력은 필수 시험 실패. 다른 동등 Boolean 그래프는 통과. 보상은 외부 PASS 플래그를 믿지 않고 공식 시험을 다시 실행합니다.
- 실제 브라우저에서 세 챕터를 포트 클릭으로 끝까지 플레이했습니다. 첫 챕터 8/8, 둘째 9/9, 마지막 57/57 회귀 통과 후 스티커·진행 3/3을 확인했습니다.
- 정상 시동에 「꺼짐」으로 잘못 예상해도 실제 READY·기대 READY는 참으로 유지되고, 예상만 재확인하며 다음 승인 진행이 잠기는 것을 확인했습니다.
- 새로고침 뒤 이어하기와 다음 챕터 복원 확인. 파일 왕복·잘못된 기록 대응은 순수 저장 시험에도 포함합니다.
- TypeScript/Vite 빌드 및 프로젝트 외부 경로 의존 검사 통과.
- **실제 portable exe를 실행해 로컬 app.asar의 게임 화면·인트로 장면이 별도 Windows 창에서 렌더링되는 것을 확인했습니다.** 해당 창은 개발 서버가 아니라 file 기반 로컬 번들을 표시합니다.
- 최초 OneDrive staging rename EPERM을 확인하고 OS 임시 폴더 staging으로 해결했습니다. 현재 package:win 스크립트에 해결 방식을 반영했습니다.
- 초기 실패 빌드가 남긴 `release/win-unpacked.tmp` 정리 명령은 실행 자동 정책에 차단되어 보존했습니다. 이 디렉터리는 게임에 필요하지 않으며 exe 하나만 복사해 실행하면 됩니다.
- 전달 exe SHA-256: `4B14FD39112342041C4622C013EAAFEBD4725558AB90E5D73ABFB21DC20D2ABB`.

## 5. 그래픽 완성도와 한계

현재: 밝은 정비소·차량·원본 고양이 3D 디오라마, 자체 2D 대사 캐릭터, 운전석 계기판, 차량 내부 단순화 그래픽, 모양별 로직 블록, 짧은 사고·성공 연출. READY 실제 출력에 차량 주변 표시 효과가 반응합니다.

추가 제작: 세밀한 차량 단면, 페달 기구·고전압 접촉기·모터의 실제 물리 애니메이션, 더 다양한 정비소, 풍부한 캐릭터 리깅. 현재 기계·SW 설명은 **교육용 개념 관계**이며 실제 ECU·고전압 회로를 재현하지 않습니다. 사고 장면도 만화적 이야기 연출입니다.

눈이 편한 밝은 배경을 적용했습니다. 실제 저시력 사용자 평가·다양한 화면 크기·GPU 성능 벤치마크는 후속 UX 시험이 필요합니다. 데스크톱을 주 대상으로 하며 전화기 세로 화면은 최적화 대상이 아닙니다. 효과음은 합성한 짧은 피드백이며 BGM은 아직 없습니다.

## 6. 기존 자료 검수

기존 아키텍처·신호·요구사항·매뉴얼은 계속 검수 대기이며 신규 정답에 사용하지 않습니다. READY_SPEC.md의 명시적 가상 사양을 재사용했습니다. 새로운 자동차 표준·안전 등급·실차 동작 주장을 추가하지 않았습니다. 외관 수리는 흰둥의 이야기 역할, 제어 기능 수정은 플레이어 역할로 분리했습니다.

## 7. 추가 예정

실제 레이싱 조작·주행 제어 연동, 정밀 내부 부품/기구 애니메이션, 다른 차량 도메인·수치·타이밍·통신·기능안전 콘텐츠, 심화 고장 추리, 게임패드 완전 지원, BGM, 시연 영상 제작. 기존 UI의 테스트·로직·판정 같은 핵심은 실제 실행됩니다. 위 부가 기능을 가짜 동작으로 완성 표시하지 않습니다.

배포 한계: Windows x64용이며 인증서 서명을 하지 않은 로컬 개발 빌드입니다. 운영체제의 실행 차단이나 보안 경고를 자동 우회하지 않습니다. 패키지 생성은 실제 설치형 런타임을 포함하므로 exe 크기는 약 112MiB입니다. 빌드 의존성 npm 감사에는 moderate 8건이 보고되어 도구 체인 업데이트 검토가 남아 있습니다. 게임 실행은 외부 서버를 호출하지 않습니다.

## 8. 후속 개발 프롬프트

### A. 첫 챕터 조작성·접근성 다듬기

> 현재 src/game의 밝은 장면 진행과 실제 엔진을 유지하며 초심자 3명 이상의 첫 챕터 플레이를 관찰하라. 운전석의 페달·시동, 내부 탐험, 포트 선택, 예상/공식 판정의 이해도를 확인한다. GuidedBoard·Cockpit·game.css의 글자 크기·대비·포트 조작·키보드 초점을 수정하라. 전체 그림 비교로 채점하지 않고 verify 기반 판정을 유지한다. 완료 기준: 혼자 첫 챕터 완료, 수정 후 25개 회귀 통과, 실제 화면 QA와 관찰 결과 기록. 기존 저장 키와 원본 게임을 변경하지 않는다.

### B. 운전석에서 내 설계 직접 체험·기계 시각화 확장

> Game.tsx의 정상 시범은 기준 그래프를 사용하고 작업대 이후 시험은 플레이어 그래프를 사용한다. 이 구분을 유지하면서 검증 후 플레이어 그래프를 Cockpit과 InsideVehicle에 전달해 조건·상태·표시를 직접 체험하는 전용 장면을 추가하라. 기존 LogicSimulation과 Snapshot을 재사용한다. 페달→입력·전이 판단→READY를 실제 출력에 동기화하고 교육용 단순화임을 명시하라. 실제 고전압 접촉기·모터 물리는 검수된 모델 없이 흉내 내지 않는다. 완료 기준: 로직 수정에 따라 관찰 결과가 바뀌고 잘못된 설계도 정직하게 표시, 상태·버튼 유지 회귀 통과.

### C. 실제 테스트 드라이브 어댑터

> docs/FOLLOW_UPS.md P2를 바탕으로 원본 C/WASM·Rapier의 실제 주행을 분석하고 필요한 모듈과 에셋을 독립 폴더 내부로 포팅하라. READY drive 허용을 실제 추진 허용 경계에 연결하되 가속/제동 로직까지 새로 학습·구현했다고 표현하지 않는다. 초심자는 주행을 건너뛰어도 검증 학습을 완료할 수 있어야 한다. 완료 기준: 실제 물리 반응과 drive 차단, 독립 exe 패키징·포트 경계 회귀, 기존 원본 보존. 완료 전 스크립트 오프닝을 조작 가능한 레이싱이라고 부르지 않는다.

### D. 배포·검증 포트폴리오

> 현재 portable exe와 story.evidence를 재사용하여 테스트별 설계 지문·입력·상태·기대/실제·판정·순서의 재현 리포트를 내보내라. 빌드 의존성 moderate 감사 8건을 조사하고 안전한 업데이트를 적용하라. Windows 서명은 사용자가 확보한 인증서가 있을 때 별도 승인된 배포 작업으로 수행한다. 게임패드·다중 해상도·저시력 UX를 검증하고 시연 영상을 제작하라. 완료 기준: 오프라인 실행·저장 복원·키보드·그래프·보상 회귀 통과, 실제 수행한 검증만 기술, 인증/ASIL/HIL 주장을 추가하지 않음.

## 9. 실행 방법

최종 파일: `release/Vehicle-Logic-Lab.exe`. 더블클릭으로 열고 「새 모험 시작」 또는 「이어하기」를 선택합니다. F11은 전체 화면, Esc는 메뉴입니다. 개발 서버·Node.js·브라우저는 게임 플레이에 필요하지 않습니다. Windows 게임 창을 실제로 띄워 두었습니다.

소스 개발은 `npm ci` → `npm run dev`, exe 재생성은 `npm run package:win`, 이미 빌드된 게임 열기는 `npm run desktop`입니다. 실행파일 하나를 다른 위치로 복사해 사용할 수 있습니다. 진행 저장은 앱의 사용자 데이터에 남습니다. 다른 PC·브라우저로 옮길 때 게임 메뉴에서 내보내기·불러오기를 사용합니다. 새 v3 게임과 v2 진행 파일 형식은 다릅니다.

구현 참고: [Electron BrowserWindow](https://www.electronjs.org/docs/latest/api/browser-window), [electron-builder portable target](https://www.electron.build/docs/targets/).
