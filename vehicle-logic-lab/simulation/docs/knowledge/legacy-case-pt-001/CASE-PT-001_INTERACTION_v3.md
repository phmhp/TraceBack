# CASE-PT-001 플레이 조작 개선 설계 / 구현 지시서

## 목표
플레이어가 조작 방법을 해석하는 부담을 줄이고 현상 관찰·요구사항 대조·입력 변경·원인 선택에 집중하게 한다. 기존 C 제어 로직, 요구사항 승인 상태, 고장 후 주행 지속 정책을 유지한다.

## 구현 범위
1. 말풍선: 다음 / 조사하러 가기를 클릭 또는 Enter로 실행. 키를 길게 눌러 두 단계를 건너뛰지 않는다. 안내가 표시된 주행 화면에서만 동작하며 X-Ray에서는 해제한다.
2. 문장/레이아웃: 소제목 앞 여백, 도움말 문단·줄바꿈·강조를 적용한다. 기술 명칭과 플레이 행동을 구분한다.
3. 조건 흐름도: 선택한 하나의 SWR 내부 조건과 결과만 그린다. 다른 요구사항으로 이동하는 화살표는 제거한다. 선행 조건, 분기, 기대 결과, 선택 시점에 해당하는 기대 경로를 표시한다.
4. 요구사항 지도: SW 구성요소별을 기본으로 한다. 처음에는 전체 노드가 보이도록 맞춘다. 휠로 포인터 중심 확대/축소, 빈 공간 드래그로 이동한다. 클릭하면 해당 노드의 상위 및 하위 요구사항·TC만 남기는 집중 보기로 전환한다. 상위 노드를 통해 무관한 형제 요구사항까지 확장하지 않는다. 전체 보기로 복귀 가능하다. 도메인은 차량 기능 분류, SW 구성요소는 구현 책임 분류라는 차이를 도움말로 설명한다.
5. 재현 시험: 신호 모니터처럼 입력 신호와 설명을 행으로 표시한다. 첫 사건에서는 요청 크기만 편집하고 방향/유효성/속력은 문제에서 주어진 PRE 조건으로 잠근다. 한 번에 한 조건만 C로 실행한다. 값을 바꾸어 다시 실행하면 이력에서 비교한다. TRIGGER는 시험 실행 동작으로, RECOVERY는 제출 이후 수정 검증으로 분리하고 임의의 복구 신호를 만들지 않는다. 두 입력 동시 입력 UI를 제거한다.
6. 원인 제출: 컴포넌트 보기와 기능 설명을 카드로 펼친다. 선택 후 오류 유형 보기를 펼친다. 선택 시험의 요구사항/결과는 자동 첨부한다. 첫 제출 및 원인/증거 분리 평가는 유지한다. 단일 시험으로도 제출 가능하며, 서로 다른 두 요청에서 비율을 확인한 증거는 별도로 평가한다.

## 검증
단일 C 시험·이력·동일 조건 수정 후 재시험, 서로 다른 실패 입력의 증거 평가, 지도 관련 노드 탐색을 테스트한다. 타입/린트와 실제 브라우저에서 Enter, 휠, 전체/집중 보기, 시험 행과 선택 카드를 확인한다. 첫 사건의 시험 범위를 넘어선 자유 시험과 ECU/통신 구현은 추가하지 않는다.

## 구현 및 확인 결과
- 말풍선: Enter 두 번으로 안내 → 조사 진입 확인. 반복 키다운은 무시하고 버튼의 기본 Enter 동작과 중복 실행되지 않도록 처리했다.
- 지도: SW 구성요소 기본 전체 맞춤(확인 뷰포트에서 15%), 휠 확대(63%), 요구사항 클릭 집중 보기(57%) 확인. eDrive 선택 시 상위 SYSR, 선택 SWR, 할당 및 관련 TC가 남고 무관한 형제 SWR는 제외됐다.
- 재현 시험: 요청 크기 한 개 편집, PRE 고정 행, 실행 버튼 옆 기대/실제 출력, 누적 결과 행을 적용했다. 새 런타임에서 90 Nm → 실제 45 Nm 확인.
- 퀴즈: 원인 컴포넌트 카드 선택 후 오류 유형 카드 노출과 요구사항 자동 연결을 확인했다. 최종 제출은 플레이어가 선택하도록 남겼다.
- 타입 검사·린트 통과. 사건 및 지도 탐색 테스트 총 10개 통과.
- 전체 지도를 한 화면에 맞추면 노드 글자가 작아진다. 휠 확대 또는 노드 선택의 집중 보기로 내용을 읽도록 구성했다.
