# 구현 결과 보고 — Vehicle Logic Lab MVP

2026-10-20. 독립 전달 경계: 저장소 최상위 `vehicle-logic-lab/`. 첨부 개발지시서 v2.0에 따라 READY 3개 미션으로 범위를 한정했습니다.

## A. 실제 구현 완료

- 블록 추가·이동·이름/신호 변경, 출력→입력 포트 연결, 연결 교체·선택·삭제, 블록 삭제, Undo/Redo, 확대·축소·화면 맞춤, 빈 공간 드래그.
- Boolean AND/OR/NOT와 state/transition을 포함하는 블록 레지스트리, 입력 누락·자료형·순환·중복 출력 검증, 실행 가능한 그래프 평가.
- 초기 상태, 상승 에지 버튼 이벤트, 틱별 최대 한 전이, 중복 전이 오류 처리, 결정론적 상태 실행. 잘못된 그래프는 검증을 통과하지 않습니다.
- 미션 1 진입 요청 계산과 실제 차량 상태 변경의 분리, 미션 2 상태 제어, 미션 3 57개 시나리오 검증.
- 계기판의 실제 상태·READY·구동 허용, 활성 블록·신호 흐름, 단계별 힌트, 정상 동작 관찰, 성공 연출, 3단계 달성도와 다음 미션 해금.
- 차량 시스템 지도, 검증된 기능 활성화, 추가 예정 도메인 표시.
- 버전별 브라우저 저장, JSON 내보내기·불러오기, 저장 오류 안내, 새로고침 복원 시 그래프 재검증. 편집 후 현재 미션의 검증 지문·완료 판정 무효화.
- 다른 도메인의 도어 잠금 데이터 샘플을 공통 엔진으로 실행하는 내부 시험.

## B. 재사용 요소

`SimulationClock.ts`, `PlaceholderVehicle.tsx`, `SoftShapes.tsx`, `CatDriver.tsx`, 차량 도면을 기존 프로젝트에서 로컬 복사했습니다. R3F Canvas의 demand 렌더링·카메라·fallback 패턴과 기존 요구사항 지도 HTML/SVG·좌표·pan/zoom 패턴을 새 편집기로 확장했습니다. 기존 지도에 편집 가능한 로직 포트/실행기는 없었으므로 해당 기능은 신규 구현입니다.

기존 C/WASM·Rapier 차량 시뮬레이션, 레이싱, 추리 및 기술 데이터는 원래 프로젝트에 보존했습니다. 새 앱에는 전체 게임을 복사하거나 물리 시뮬레이션을 대체하지 않았습니다. 상세 판정과 복사 파일 SHA-256은 [REUSE_AUDIT.md](REUSE_AUDIT.md)에 있습니다.

한계: 차량 모델과 계기판을 기본 브라우저 크기에서 시각 확인했습니다. 별도 모바일 기기·GPU 성능 벤치마크는 수행하지 않았습니다. 빌드에는 Three.js 포함 단일 JS 청크 약 1.16MB(압축 약 328KB)의 크기 경고가 있으며 실행 실패는 아닙니다. 폰트는 로컬 번들이고 서버 의존은 없지만 정적 글꼴 여러 굵기를 포함합니다. 코드 분할·글꼴 최적화는 후속 성능 작업으로 남습니다.

## E. 추가 예정

테스트 트랙 연동, 문제 해결 챌린지, 상세 E/E·SW 지도, 다른 차량 기능 도메인, 고품질 차량·배터리·모터·열관리 애니메이션, 고급 보상·커스터마이징·오디오. 필요한 실제 모델·검수 데이터·통합 검증 없이 작동하는 것처럼 표시하지 않습니다. 현재 고양이 애니메이션은 보존된 원본 코드이며 신규 UI에 표시하지 않습니다.

기능별 목적·필요 입력·재사용 대상·주의사항은 [FOLLOW_UPS.md](FOLLOW_UPS.md)의 스텁 목록을 확인하세요.

## F. 기존 차량 데이터 검수

- 신규 READY: **명시적 교육용 가상 사양**을 요구사항·기대값·실행 결과와 대조했습니다. 실제 차량 기술 검수 완료를 주장하지 않습니다.
- 기존 요구사항·신호·인터페이스·아키텍처·사례·매뉴얼: 목록화 및 재사용 후보 분류 수준. **검수 대기**, 신규 정답/채점에 미사용.
- 사용 부적합: 이번 작업에서 특정 자료를 확정하지 않았습니다. drift 실패는 생성물 불일치 증거일 뿐 기술 오류 판정이 아닙니다.
