### 남은 에피소드와 완료 조건

1. **전원 접속:** BMS 사용 가능 판단 → START 요청 → 프리차지·접촉기·READY 상태 전이 → 배터리 출력 상한. 각각 저장 가능한 Function 그래프와 정상/경계/고장 입력 시험, 같은 차량의 실제 전력 차단·허용 확인.
2. **충전·저전압·열:** OBC 충전 허용, DC/DC·12V 공급, 배터리·모터·인버터 온도에 따른 펌프·팬·출력 제한. 차량 상태와 충전·냉각 장치를 같은 틱으로 연결.
3. **구동 완성:** D 기어 인터록, 인버터 토크 추종, 감속·차동기어와 좌우 뒷바퀴. 모터 명령과 바퀴 전달의 경계를 검증.
4. **제동 완성:** 회생·마찰 배분, 휠별 ABS/EBD, ESC 개입. 휠 속도·차체 자세 입력에 따른 네 바퀴 제동력과 차량 감속을 검증.
5. **조향 완성:** 토크 센서→EPS 보조 토크·전류→랙·타이로드→좌우 앞바퀴 및 고장 대응. 운전자 기계 연결과 모터 보조를 구분.
6. **E/E·진단:** ECU 간 신호 유효성, 통신 지연·상실과 진단 반응, 도메인 간 출력 통합. 같은 결함을 Function·ECU·차량 수준에서 재시험.

각 에피소드는 **플레이어 그래프 저장 → 독립 정상·경계·고장 판정 → `vehicleSystems`와 물리 명령에 실제 사용 → 우측 장치·신호·3D 반응 동기 표시**가 모두 되어야 완료로 바꾼다. 이 기준 전에는 설명 카드나 단일 틱 상태 계산을 제작 완료로 표시하지 않는다.

검증: `npm test` 148/148, `npm run build`, `npm run check:independence`, `npm run test:domain-ui`, `npm run test:game-ui` 통과. UI 검사는 실제 React 진행·오른쪽 경로·BMS 분리·FINISH→시상대·차고지 엔딩을 확인한다. 브라우저에서 1063×704 설계 지도의 기능·시스템, E/E, SW 관점 화면을 직접 확인했다. 전체 플레이의 GPU 화면과 신규 사용자 검수는 남았다.

후속 작업 프롬프트: 전원 접속 에피소드부터 시작해 각 Function의 입력·출력·독립 정상/경계/고장 사례를 `domainTraining.ts`에 정의하고, 플레이어가 저장한 그래프만 `WorkshopController`의 동일 틱 시스템 상태와 Rapier 명령에 반영한다. 테스트가 차량 상태·우측 경로·3D 장치 반응까지 확인되기 전에는 `완료`로 바꾸지 않는다. 이어서 충전·저전압·열 → 구동 → 제동 협조 → EPS → E/E·진단 순으로 같은 기준을 적용한다.

아래 절은 변경 당시의 기록이다. 현재 완료·미완료 판정은 이 절을 우선한다.

## 2026-10-30 UX·기능 지도 후속

- **완료:** 블록 단일 클릭 설명 복원, 블록 몸체로 빈 입력 포트 연결, 자료형이 다른 선도 그린 뒤 실행 오류 표시. 지연 없는 순환은 계속 차단한다.
- **완료:** System/Domain/Function 경로를 서로 다른 확대 수준으로 열고, 주행 시나리오 도메인 도식·기능별 차량 단면 신호 그림·EV 선택 구성 미리보기를 추가했다.
- **완료:** 복구 추적에서 현재 단계 부품과 연결만 컬러로 강조한다. 마지막 지도의 실제 주행 기록 탭을 제거하고 Function 선택 시 저장된 블록 그래프를 지도 안에 표시한다. 아래 말풍선은 로직 도움말 단계를 이전/다음으로 넘기고 복구 장면의 현재 단계를 설명한다.
- **부분 완료:** 그림은 코드로 그린 차량 단면·신호 도식이며 실제 3D 기구 동작과 블록 포트값이 같은 시간축으로 완전히 묶이지 않았다. 기술 선택지는 미리보기이며 차량 실행기의 구성을 바꾸지는 않는다. [UX 검토와 실행할 후속 작업](UX_REVIEW_2026-10-30.md)에 남은 범위와 우선순위를 기록했다.

## 2026-10-29 최신 판정 · 기술 지도·기능 경로·게임 화면 정리

- **완료:** EV 기술 선택 카드에 각 구성의 효과를 바로 표시하고 별도 비교 화면·약어 목록을 제거했다. 기능 트리는 기본 접힘으로 유지하고 Domain 아래 목적별 묶음을 두었다. 기능 선택 시 입력→SW 계산→출력 신호→액추에이터·기계→차량 반응을 한 경로로 재생한다. 전력/신호/기계 분리 탭은 표시하지 않는다.

- **설계 문서 완료, 제작 에피소드 미완료:** [EV 에피소드·계층 매트릭스](EV_EPISODE_AND_HIERARCHY_MATRIX_2026-10-28.md)에 기준 차의 System/Domain/Function ↔ ECU/SWC/Runnable, 일곱 에피소드의 선택지와 미완료 기능, 검증 효과를 전부 명시했다. 문서·선택형 실험실을 플레이어 제작 완료로 세지 않는다. 현재 직접 제작은 여전히 6개다.

## 2026-10-28 실행 기능 추가 점검

- `signalBlocks.ts`에 참조 그림의 39종 블록을 등록하고 산술·논리·버스·룩업·저장·태그·트리거·지연·차트의 이산시간 실행 규칙을 구현했다. `BlockLibraryLab.tsx`에서 입력/설정을 바꿔 실행하고 현재 설계도에 블록을 넣을 수 있다. 지연 블록을 통한 피드백은 허용하며 지연 없는 순환은 거부한다. `tests/signal-blocks.test.mjs`가 연산·상태·중첩·저장 후 평가를 확인한다. **MathWorks 전체 블록 옵션과 Stateflow 실행 의미까지 동일하다는 뜻은 아니다.** 특히 Chart/Enable/Trigger는 이 게임의 고정된 샘플 규칙이며 다중 출력 버스 포트와 모든 자료형 옵션은 남아 있다.
- `vehicleSystems.ts`에 전원 접속/프리차지, 배터리 가용 토크·열 제한, OBC·DC/DC, 후륜 토크, 회생·마찰 배분과 ABS/ESC, 전륜 조향·EPS, 진단/차단의 상태 모형을 추가했다. 최종 설계 지도에서 입력을 조작하고 틱을 실행할 수 있다. 절연 이상과 열 제한은 실제 주행 컨트롤러의 추진 차단/토크 상한에도 연결해 시험했다. **플레이어가 직접 구성하는 블록 미션은 여전히 6개이며, 충전·ABS·EPS 등 전체 기능의 플레이어 제작/주행 물리 반영은 완료가 아니다.**
- 3D 메쉬에서 닫힌 듯 보이던 차체 윗면을 낮추고 열린 실내·전면 유리·시트/롤후프·헤드램프·휠 디테일과 고양이 팔 형태를 개선했다. 브라우저 바깥 주행 시점에서 오픈톱 형상을 확인했다. 충돌 뒤 얼굴은 보이도록 카메라를 조정했지만, 제목 원화 수준의 정식 전용 모델/리그와 전 장면 GPU 품질 승인, 자연스러운 표정·신체 리깅 컷신은 여전히 남아 있다.
- 컵은 시드별로 중간 게이트와 수집 위치가 바뀌며 마지막 160m 골과 물리 판정은 유지한다. 굽은 도로·장애물·경쟁차 전략을 포함한 완전한 코스 생성은 아니다.
- 회귀: 단위 129/129(라이브러리/Subsystem 저장 재로드·독립 상태·연결되지 않은 Scope 실행/단일 샘플 시계·From/Goto 경로 격리 포함), `test:domain-ui`, `test:campaign-ui`, `test:game-ui`, `build`, `check:independence` 통과. 브라우저 바깥 주행과 앞바퀴 좌우 장착/재로드 화면 확인. Windows 포터블과 전 카메라 수동 검수는 아직 하지 않았다.

실제 브라우저 조립 검수에서 좌우 바퀴가 저장 레코드에는 모두 체결되어도, 선택하지 않은 한쪽에 투명화 효과가 적용되어 한 개만 장착된 것처럼 보이는 결함을 확인해 수정했다. 앞/뒤 좌우 한 쌍은 동시에 선명하게 표시하고 각 상태 표기도 `왼쪽`/`오른쪽`으로 구분했다. 재로드 뒤 앞바퀴 두 개가 차대에 남아 있는 것을 확인했다. 오른쪽 부품 미리보기의 해상도 상한을 높이고 3D 작업대 라벨을 없애고 HTML 상태표/설명 글자 대비를 높였다. 충돌 장면은 실제 브라우저에서 얼굴이 좌석에 가려지던 카메라를 조정해 파손된 차 앞에서 슬픈 얼굴이 보이도록 했다. 이는 컷신 리깅과 제목 원화 수준의 3D 일치를 승인한 것은 아니다.

## 2026-10-28 후속 점검

차량 구성을 **단일 모터 후륜구동 BEV·앞바퀴 2륜 조향·VCU/제동/조향 기능별 제어기**로 고정하고, `DomainCampaign.tsx`의 설계 화면에 담당 제어기·Application SW 수준·입출력·물리 효과를 표시했다. `domainTraining.ts`의 운전 관찰 문구에서 “페달을 놓으면 정차”, “모든 바퀴 조향 가능”처럼 읽히는 모순을 바로잡았다. `domains.ts`에 부품 분류를 추가하고 차체 조립과 바퀴 도식의 앞→뒤 순서를 통일했다. 최종 지도에는 차량 구성과 기능 전체 목록(직접 구성/차량 기반/다음 설계)을 추가했다. 배선은 6개가 순서대로 나타난 뒤 카울을 닫도록 바꾸고 중간 상태 회귀를 추가했다. 파일별 데이터가 어느 화면에 쓰이는지와 각 관점의 경계는 [콘텐츠·아키텍처 검토](CONTENT_ARCHITECTURE_AUDIT_2026-10-28.md)에 기록했다.
