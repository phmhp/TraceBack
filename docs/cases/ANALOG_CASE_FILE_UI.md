# 고장 조사 파일 — 서류형 UI 설계 및 반영

현재 C/WASM 결함·판정·수정 검증은 유지한다. 화면은 고양이 운전자의 보고서를 접수한 분석가의 서류철이다.

- 시작 서류: 고장 보고서. 입력 신호 / 제어 SW 처리 과정 / 차량 출력의 세 영역. 신호 설명은 hover/focus title로 제공한다.
- 안내 질문, INVESTIGATING, 중복 홈과 돌아가기 버튼, 재생 영역의 기술 설명은 제거한다.
- 기능 구조는 차량 전체 기능 분류와 이번 사건의 실행 경로를 구분한다. Propulsion 영역을 열어 PropulsionFunction/VMC/eDrive를 동료 구성요소로 확인한다. VMC/eDrive를 PropulsionFunction의 실제 내부 함수로 재분류하지 않는다.
- 기능 명세는 입력/출력 2열 표와 SYSR/SWR/TC 분류로 표시한다.
- 요구사항은 단일 System → 기능 영역 → 구성요소 분류를 사용한다. 분류는 요구사항 파생 관계가 아니며 실제 SYSR/SWR/TC 연결선은 도메인 간에도 보존한다. 가짜 최상위 SYSR를 만들지 않는다.
- 요구사항 지도가 기본이다. 확대 시 ResizeObserver가 fit을 반복하던 동작을 없앤다. 문서 선택과 지도 선택은 같은 requirement ID를 공유한다.
- 시험실은 기능과 TC/판정 기준을 먼저 선택한다. 다른 문서에서 관련 시험을 열면 선택 문맥을 전달한다.
- 단서는 신호 대조 / 시험 결과 / 기준 문서를 참조한다. 메모판과 제출 화면 모두 ID에 더해 실제 내용·값을 표시한다. 메모판에서 원본을 다시 열거나 제출 근거로 선택한다.
- 조사 메모는 명시적으로 저장한다. CaseState에 보존하며 export JSON에 포함한다. 페이지 새로고침/세션 초기화를 넘는 영속 저장은 이번 범위에 없다.
- 시각 표현은 크림 종이, 민트 서류 색인, 테이프와 핀, 인화지 프레임이다. 장식은 CSS로 작성하고 기존 게임 자산 및 폰트를 사용한다.
