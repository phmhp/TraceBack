# 남은 작업의 순서와 완료 기준

## 2026-10-29 START 미션 후 판정

전력 에피소드에서 플레이어가 만드는 기능은 BMS PackSafe → VCU StartPermit → VCU PowerEnable의 세 단계다. START 미션의 상승 이벤트·P·브레이크·플러그·BMS 판단은 실제 프리차지 상태기의 입력으로 연결했다. 직접 제작 모델 총수는 **8개**다. `npm test` 146/146, 빌드, BMS/START UI 회귀가 통과했다.

**다음 개발 단위:** 프리차지 전압 비율·시간 초과·접촉기 명령의 상태전이를 플레이어 제작 그래프로 나누고, 접촉기/절연 감시 부품과 배선을 조립 흐름에 넣는다. 상태기와 실제 주행·고장 복귀·저장 복귀가 한 계약으로 검증돼야 전원 에피소드를 완료로 판정한다. 그 뒤 충전·DC/DC·열, 제동 협조·휠별 안정 제어, EPS·진단, ECU 통신 경계, 3D·블록 동등성, 전체 플레이 검수를 진행한다. 제공 상태기의 존재만으로 접촉기 기능을 플레이어 제작 완료로 세지 않는다.

## 2026-10-29 BMS 기능 제작 후 갱신

전력 에피소드에 SOC·온도·절연 상태를 판단하는 BMS `PackSafe` 미션을 추가했다. 직접 제작 모델은 6개에서 **7개**로 늘었다. 그래프의 출력은 VCU 전력 허용 입력을 거쳐 실제 차량 구동력을 차단할 수 있고, 같은 물리 틱의 BMS→VCU→전력/액추에이터 경계를 최종 주행 기록에서 확인한다. 완성 차량 시험 주행에서는 정상·SOC 경계·온도 경계·절연 이상을 같은 차로 다시 시험한다. 옛 저장의 완료 상태는 보존하며, 자동 보충한 BMS 그래프에는 `assisted` 기록을 남긴다.

**3단계 전원·READY는 여전히 부분 완료**다. 다음 구현 단위는 플레이어가 프리차지·접촉기 상태전이와 START/READY 인터록을 그래프로 만들고, 접촉기/절연 감시 장치를 조립·배선하고, 저전압·타임아웃·절연 이상 사례를 검증하는 것이다. 그다음 충전·DC/DC·열, 제동 협조·ABS/EBD/ESC, EPS·진단, 전용 3D 순으로 진행한다. 전용 3D와 39종 블록의 MathWorks 전체 동등성은 여전히 미완료다. 이번 회귀는 `npm test` 143/143, 빌드, 독립 검사, 게임 UI 정적 검사를 통과했다.

`npm run test:bms-ui`도 통과했다. 오래된 `test:domain-ui`는 현재 화면에 없는 `가속 페달` 버튼을 찾는 지점에서 실패한다. 해당 전체 주행 스크립트 갱신과 실제 브라우저 GPU 시각 검수는 별도 후속 작업이다.

## 2026-10-29 현재 완료/미완료 판정

당시 **완료한 단위**는 두 가지다. 첫째, 한 시험 사례의 그래프가 실제로 방문한 블록·선 값과 Subsystem 내부 경로를 순서대로 기록하고, 로직 실행 탭에서 단계별로 보여준다. 둘째, 물리 실행 직후 같은 `tickId`의 운전자 입력·당시 여섯 제작 모델의 블록 중간값·SW 토크 명령·시스템 제한·액추에이터 명령·차량 속도/가속도를 최대 60초 기록한다. 최종 지도에서 틱, 신호 경계, 기능 모델, 블록을 선택해 3D 강조와 함께 확인한다. 시험 사례 재생과 실제 주행 기록은 별도 화면이다.

이후 **기능 출력 첫 불일치**와 마지막 완주 기록의 IndexedDB 저장·복원을 추가했다. SW 화면에는 기존 ①/② 탭과 별개로 `실험 · 단계형 퍼즐`을 두어 관찰→예측→구성→실행→새 조건을 시험할 수 있다. 이 탭은 미션 판정 로직을 바꾸지 않는다. 사용자 비교 실험과 GPU 화면 검수는 남았다.

| 계획 단계 | 현재 판정 | 남은 완료 조건 |

다음 개발 단위는 **전원·READY 에피소드의 전체 세로 연결**이다: 부품·배선 → BMS/접촉기 로직 → 정상/절연 이상/타임아웃 시험 → 같은 틱의 물리·3D 결과 → 최종 지도. 이후 충전·저전압·열, 제동·조향 심화, E/E 통합 순서로 같은 계약을 반복한다. 단순 상태 계산이나 선택형 카드만으로 제작 완료를 선언하지 않는다.

## 초기 구현 기록: 최종 설계 지도의 첫 연결

`VehicleBlueprint`의 기능·단계 선택을 3D 뷰와 공유한다. 현재 단계의 장치를 표기하고, 신호/기계 경로에 색을 주며, 계산된 토크·제동력·조향각을 전용 3D 동작에 전달한다. 기존 오픈톱 차체의 반투명 외장을 얹고, 3D 바로 위에서 이전/다음 단계와 기능을 선택할 수 있다. 단계의 수치는 현재 저장된 그래프를 `executeVehicle`로 평가한 사례에서 온다.

**현재 판정:** 기능 원리 재생은 여전히 샘플 한 건을 설명한다. 별도의 실제 주행 기록은 `tickId`별 여덟 제작 모델의 블록값과 물리 결과를 기록하고 저장한다. ECU 송수신 상세와 차량 전체 자세 재생은 남았다. 차량 형상은 기존 절차형 3D를 개선한 것이며 첨부 이미지 수준의 전용 내부 단면 자산도 아니다. 첨부 이미지는 정보 구조와 시점의 참고 자료이며 그 차종·원화·라벨을 복제하지 않는다.

## 에피소드별 동일 계약

기준 차량은 한 대의 단일 후륜 모터 BEV, 앞바퀴 기계 연결 EPS 조향, 기능별 분산 ECU다. 다른 구동축·조향·ECU 배치는 기술 선택 카드에서 비교하되, 실제 선택 가능 차량으로 만들 때에는 별도 사양 ID와 부품·로직·시험·물리 경로를 함께 구현한다. 단순히 카드 문구를 바꾸는 것으로 다른 차량을 만든 것으로 세지 않는다.

필수 기능과 현재 상태의 전체 표는 [EV 에피소드·계층 매트릭스](EV_EPISODE_AND_HIERARCHY_MATRIX_2026-10-28.md), 요청별 현황은 [요청 추적표](REQUEST_2026-10-27_STATUS.md)에 있다. 이 계획의 단계 1~9는 순서와 완료 기준이며, **전체가 아직 완료되지 않았다.** 이번 변경은 2단계의 최종 화면 시각화 일부를 먼저 연결한 것이다.
