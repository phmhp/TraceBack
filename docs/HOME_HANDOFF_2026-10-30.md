## 남은 작업 · 구현 순서

아래는 **구현되지 않았거나 부분 구현**된 작업이다. `vehicleSystems.ts`의 계산, 설명 카드, 부품 선택지만으로 `플레이어가 제작 완료`라고 표시하지 않는다. 첫 완주를 다시 길게 늘리지 말고 완주 뒤 차고의 **추가 의뢰 에피소드**로 구성한다. 각 에피소드는 관찰 → 부품/배선 → Function 퍼즐 → 정상·경계·고장 시험 → 같은 차량의 동작 → 기능 추적 → 차고 복귀의 짧은 루프다.

1. **전원 접속·READY:** 플레이어가 BMS 사용 가능 판단, START 상승 이벤트 허용, 프리차지/접촉기/READY 상태 전이, 배터리 출력 상한을 순서대로 제작한다. 제공 BMS/START 그래프를 새 의뢰의 답으로 자동 승인하지 않는다. 저 SOC, 과열, 절연 이상, DC 링크 전압 미달, 프리차지 시간 초과에서 실제 접촉기와 구동력 차단을 판정한다.
2. **충전·12V·열관리:** OBC 충전 허용, DC/DC·12V 공급, 배터리·모터·인버터 온도에 따른 펌프·팬과 출력 제한을 각각 제작한다. 충전 플러그·기어·온도·저전압 부하를 바꾸면 동일 차량 상태와 장치 애니메이션이 바뀌어야 한다.
3. **구동 완성:** 기존 운전자 토크 요청과 D 기어 인터록을 재사용하고, 토크 상한·인버터 응답, 감속기·차동기어에서 좌우 뒷바퀴까지의 전달을 제작·검증한다. 전기 명령과 기계 축 토크의 경계를 구별한다.
4. **제동 완성:** 회생/마찰 배분, 네 바퀴별 ABS/EBD, ESC 개입을 제작한다. 휠 속도·슬립·요 오차·배터리 충전 가능량에 따른 실제 바퀴 제동력과 차량 감속을 확인한다.
5. **조향 완성:** 기준 차량은 운전대와 랙의 기계 연결이 남은 EPS다. 운전자 토크와 EPS 보조 토크/전류, 랙·타이로드·좌우 앞바퀴, 보조 고장 반응을 구분해 제작한다. 각도 변환 퍼즐만으로 EPS 완료라고 표시하지 않는다.
6. **E/E·진단:** ECU 간 포트와 신호 주기·유효성·지연/상실, 진단 반응을 제작한다. 같은 결함을 Function 출력 → ECU 경계 → 도메인 조합 → 차량 동작에서 추적한다. 시스템 시험에는 도메인별 BMS 단독 사례를 다시 넣지 않는다.
7. **동일 틱 재생:** 저장한 그래프의 입력·블록 포트값·ECU 출력·배선·3D 액추에이터·Rapier 물리 반응에 같은 `tickId`를 부여해 재생한다. 현재 지도의 단계 재생은 개념 시연과 예시 입력이며 실제 한 틱의 완전 동기 재생은 아니다.
8. **전용 3D와 UX 검수:** 차·고양이·내부 단면·접촉기/냉각/제동/EPS 장치를 전 장면에 같은 디자인과 색으로 제작하고, 관통·떨림·글자 선명도·GPU 성능을 확인한다. 1063×704와 작은 화면에서 우측 필수 정보가 잘리지 않고, 상세 정보는 토글에 남는지 플레이 전체를 검수한다.
9. **블록 사양 검증:** 39종 블록은 게임 실행기가 있으나 MathWorks Simulink의 전체 파라미터, 자료형, 샘플 시간, Subsystem/Stateflow 의미 동등성은 입증되지 않았다. 이를 별도 사양 대조와 독립 시험으로 확인하고 잘못된 동일성 주장을 피한다.
10. **학습 효과 검증:** 단위·ECU 통합·차량 시험의 차이를 같은 결함으로 경험하게 하고, 신입 사용자에게 현재 편집기와 단계형 퍼즐의 이해도·완주 시간·이탈 지점을 비교한다. 추가 의뢰가 늘어도 첫 완주의 도메인당 한 퍼즐 원칙을 유지한다.

각 새 Function의 **완료 조건**: (a) 요구사항·포트·ECU/SWC/Runnable 할당, (b) 플레이어 그래프 저장과 재진입, (c) 독립 정상·경계·고장 사례, (d) 그래프 출력이 같은 틱의 `WorkshopController`/`vehicleSystems`/Rapier 명령에 반영, (e) 우측 장치·신호와 3D 실제 반응, (f) 이전 저장 마이그레이션 및 회귀 테스트. 하나라도 빠지면 추적표에 `부분` 또는 `미완료`로 남긴다.
