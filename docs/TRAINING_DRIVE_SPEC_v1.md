# TRAINING-DRIVE-1.0 — 구동 심화 교육 사양

상태: **명시적 가상 교육 사양**. OEM 양산 사양·캘리브레이션·안전 표준·AUTOSAR 적합성을 주장하지 않는다. 이전 READY 사양을 대체하지 않고 별도 수치 모듈로 연결한다.

## 1. 범위와 정상 동작

입력은 페달 A/B[%], 신호 나이[ms], 제동[%], READY[bool], 기어[P/R/N/D], 가용 토크 상한[Nm]. 출력은 전진 기능의 비음수 토크 명령[Nm]이다. 음의 회생 토크·후진 추진·ABS·배터리 물리·모터 전기 동특성은 이 모듈의 범위가 아니다.

정상 입력 A=B=50%, 나이 20ms, 제동 0%, READY=true, D, 상한 180Nm에서 목표는 90Nm. 초기 명령은 0Nm이며 첫 20ms 실행 후 1.2Nm, 75번째 실행 후 90Nm이다. 모든 시나리오는 독립적으로 초기 상태 0부터 시작한다. 표본 시간은 해당 실행을 마친 시점으로, tick 0은 0.02s다.

## 2. 요구사항

| ID | 기준 |
|---|---|
| DRV-01 | A/B 각각 0~100%, 채널 차이 ≤10%p, 나이 0~100ms. NaN/무한대·범위·불일치·지연 위반 시 같은 틱에 명령 0. |
| DRV-02 | 품질 정상 + READY + D + 제동 <5%에서 요청 = A×1.8Nm/%. |
| DRV-03 | 목표 = min(요청, 가용 상한). 상한 0~180Nm은 시험 전제. 상한 감소는 변화율보다 우선하여 명령도 즉시 상한 이하. |
| DRV-04 | 제동 ≥5%, READY=false, D 이외 기어에서 같은 틱에 0. 조건 복구 후 0부터 재증가. |
| DRV-05 | 증가 60Nm/s, 감소 120Nm/s. 실행 간격 20ms에서 +1.2/-2.4Nm 이내. 차단과 상한 감소가 우선. |

유효하지 않은 상한·실행 간격·그래프 구조는 명시적인 실행 오류이며 명령은 0으로 설정한다. 이는 교육용 오류 처리이지 검증된 기능 안전 메커니즘이라는 뜻은 아니다.

## 3. 실제 설계·실행

출력→입력의 방향과 %, ms, Nm, flag 단위를 검사한다. 입력 포트마다 하나의 송신자를 갖고 같은 입력 재연결은 교체다. 같은 틱의 순환은 거부한다. 품질 검사 → 이득 → 상한 → 허용 조건 → 상태 보유 변화율 → 명령 경계의 실제 연결을 실행한다. 변화율 블록은 각각 별도 이전 상태를 보유한다. 편집기는 일곱 종류의 고정 블록을 제공하며 수치 파라미터와 배선은 편집 가능하다. 임의 블록 라이브러리·코드 생성기는 아니다.

기대값은 학습자가 편집하는 그래프나 파라미터를 읽지 않는 `torqueSpec.ts`의 고정 사양 오라클이다. 구조가 다르더라도 관찰 동작이 같으면 통과할 수 있다. 제공하는 19개 시험의 통과는 전체 입력 공간이나 안전성을 보장하지 않는다.

## 4. 시험과 남는 근거

정상 0/50/100%, 상한 45Nm, 상한 급감, 제동 4.99→5%, READY 해제, P/R/N, 채널 차이 10/10.01%p, 신호 나이 100/101ms, 범위 ±0.01%, 최초 증가·감소, 고장 후 복구를 시험한다. 요구사항↔시험 ID, 각 틱 입력/기대/실제/오류, 최초 실패, 그래프와 사양 버전, 예제 불러오기 이력을 JSON으로 내보낸다.

설계 식별자는 변경 추적용 FNV 해시이지 서명·보안 증명·인증 ID가 아니다. 저장된 완료 표시는 로드 시 실제 시험을 다시 실행하여 확인한다. 수정하면 완료 표시가 해제된다. READY 모험 저장과 심화 설계 저장은 별개 키다.

## 5. 물리·그림·AUTOSAR의 경계

- 모터/감속기/페달/캘리퍼 모형은 명령과 입력을 시각화한다. 회전 속도는 실제 측정 RPM이나 에너지 계산 결과가 아니다. 부품 배치는 설명용이다.
- 차량 반응 모드는 기존 C/WASM→Rapier 명령의 **추가 상한**으로 학습 토크를 적용한다. 원본 C 명령을 덮어쓰지 않고 적용 추진력을 별도 표시한다. C가 더 작은 토크를 요청하거나 차단하면 학습기의 큰 값이 이를 강제하지 않는다.
- 단위 시험은 고정 20ms 논리 실행이다. 실시간 화면은 타이머로 모델을 구동하고 100ms마다 표시한다. 물리는 기존 약 60Hz 실행기에서 최신 표시 상한을 읽는다. 이는 동일 시계의 20ms 제어기–플랜트 연성 시뮬레이션이 아니다. 리플레이의 틱 이동은 논리 기록 이동이며 물리 상태 seek가 아니다. 물리 PASS를 이 화면에서 판정하지 않는다.
- READY→구동의 세 가지 검사는 정상 시동/브레이크 없는 시동/시스템 미준비 기능 경계 계약이다. 전체 차량 통합·실시간 스케줄링 검증과 다르다.
- SWC, Runnable, 포트, RTE, BSW 표시는 설계 관점 매핑이다. 실제 RTE 생성·BSW/MCAL·OS task·ARXML·ECU 배포·HIL은 구현하지 않았다.

## 6. 후속 깊이

다음 단계는 같은 시계의 초기조건/입력/지연/플랜트 로그와 독립 물리 기준을 결합하는 것이다. 그 뒤 전제조건의 동등 분할, CAN/E2E의 유효성·지연·손실, 모드/제동/에너지 경계, 진단 디바운스·복구를 각 검수된 모듈로 확장한다. 기존 참고자료의 DRAFT를 검토 없이 양산 정답으로 쓰지 않는다.
