`DomainCampaign.tsx`는 진행·화면·상호작용을 조립한다. 개념의 원천 데이터를 화면 안에 계속 하드코딩하지 않는 것이 목표다. `domainTraining.ts`의 `MODEL_SPECS`는 **6개 Application 기능의 블록/입출력/시험 사양**이지 차량 전체 시스템 목록이나 ECU 토폴로지가 아니다. `domains.ts`는 **부품 묶음·물리 역할·현재 차량 구성**을 다룬다. 기능 목록은 `VEHICLE_FUNCTIONS`에 별도로 둔다.

## 관점과 차량 구성에 대한 결정

- **차량 변형**: 한 대의 단일 모터 후륜구동 BEV, 앞바퀴 두 개 조향. 네 바퀴를 모두 장착하지만 네 바퀴가 모두 조향하거나 구동하는 것은 아니다.
- **기능 분해**: 차량 → 에너지/구동/제동/조향 → 기능 → 계산 로직. 이는 탐색 경로이며 물리 부품의 조립 계층과 동일하지 않다.
- **물리 경로**: 배터리 DC → 인버터 → 모터 → 감속·차동기어 → 좌우 뒷바퀴. 브레이크는 별도 마찰 경로이고, 조향은 앞바퀴 랙 경로다. 정보/전력/기계 에너지를 구분한다.
- **E/E 할당**: VCU, 제동 제어기, 조향 제어기가 기능별로 나뉜다. 게임에 단일 주행통합제어기나 HPC/Zone ECU가 등장하는 것으로 읽히면 안 된다. `Domain`은 기능상의 묶음이고 물리 ECU 통합을 자동으로 뜻하지 않는다.
- **SW 수준**: 현재 블록은 제어기 안의 Application 기능 계산(허용, 목표값, 인터록, 출력 선택)이다. AUTOSAR의 Application/RTE/BSW 구분, 실 ECU 매핑, 런너블 스케줄링, 모터 전류 폐루프와는 별도 축이다.
- **검증 수준**: 기능별 입력·출력 사례와 통합 물리 모형 주행. 실제 부품/ECU/차량 시험과 혼동하지 않는다.

## 기능 완성 판정에 남은 차이

현재 사용자가 직접 만드는 계산은 전력 허용, 운전자 토크 요청, 전진 구동 인터록, 마찰 제동력 요청, 앞바퀴 각도 요청, 도메인 출력 선택의 6개다. READY 상태기, BMS 신호, 인버터 내부 응답, 수동 현가·차량 운동 등은 차량 기반 동작이다. 고전압 접촉기·프리차지, 재충전/OBC, DC/DC·12V, 냉각, 회생 제동·ABS/EBD/ESC, EPS 보조, 신호 진단·고장 반응은 기능 목록에 있지만 플레이 가능한 퍼즐/검증까지 연결되지 않았다. 목록 추가만으로 “필수 기능 모두 제작”으로 판정하지 않는다. 어떤 것이 필수인지는 구체 차량·사용 시나리오·규제에 따라 결정해야 한다.

## 요청 추적표의 잔여 구현 단위와 인수 기준

1. **블록 라이브러리**: 참조 이미지의 From/Goto, Sum/Product, Bus, Lookup, Delay/Memory, Data Store, Mux/Demux, Switch, Chart 등을 포트 타입·시간 상태·파라미터·실행 의미·저장 호환성까지 정의하고 각 블록의 독립 시험과 플레이어 팔레트 검증. 단순 외형 추가로 완료 처리하지 않는다.
2. **필수 기능 확장**: 전원 접속/READY 상태 전이 → BMS·가용 출력/열 → 충전·저전압 → 제동 협조·안정화 → 조향 보조·진단 순으로 각 기능마다 부품, 신호, 로직, 독립 기대값, 실제 차량 반응을 연결. 먼저 차량 변형과 검증 경계를 확정한다.
3. **아트·애니메이션**: 제목 원화의 차량·고양이를 3D 전용 메시/재질/리그로 재제작하고, 모든 카메라에서 관통·지면 접촉·글자 선명도·떨림·표정 전환을 캡처로 확인한다.
4. **배선·카울**: 현재는 6개 경로가 차례로 나타나고 카울을 마지막에 닫는다. 각 커넥터를 손으로 체결하는 모션과 실제 3D 카메라별 접촉 확인, 정지/재개/재진입의 전체 수동 검사는 남아 있다.
5. **추가 UX/회귀**: 작은 화면의 블록·지도 실사용 검사, 레거시 `check-campaign-ui.mjs`의 현 도움말 동선 갱신, 실제 Windows 실행파일 및 주행 전 구간 수동 검증.
6. **선택 아이디어**: 다차량 차고지, 전륜·사륜구동, RWS, 회생제동, 도메인 통합/HPC/Zone 구성 옵션은 현재 차량과 별도 세이브 스키마/물리/검증 규칙을 설계한 뒤 차기 제품 단위로 평가한다.
